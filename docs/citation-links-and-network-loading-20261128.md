# 引用来源与聊天资源的按需加载

2026-11-28。

## 问题和原因

引用展开区域把 `UrlCitation.groundingSegments` 的模型回答片段直接交给普通 Text 显示，既重复正文，也暴露 Markdown 的 `**`、反引号等标记；有图片 URL 时还会直接加载引用图片。知识库引用则始终展示摘录卡片，不能进一步查看精确分块。

链接还存在这些隐式网络入口：

- 来源图标通过 `favicone.com/<host>` 加载，会将来源域名交给第三方。
- Google 返回的搜索建议 HTML 允许加载 HTTPS 图片。
- 远程 Markdown 图片与搜索结果图片进入布局后直接交给 Coil 加载。
- GitHub 卡片在可见区域停留后调用仓库 API。缓存过期、重新进入视野或重新订阅时，可能再次刷新。
- 抽屉中的更新提示在订阅 `updateState` 时自动检查最新版本。离开页面后停止订阅，再次进入且内存中的 30 分钟缓存过期时，会再次请求。

用户提供的日志 `rikkahub-1795801945884.log.txt` 实际仅有一条请求记录，目标是本仓库 `/releases/latest`。响应 JSON 包含 author、assets、tarball 等许多 URL 字段；这些字段本身不表示应用逐个请求了 URL。这条请求属于版本检查，不是聊天仓库卡片的元数据请求 `/repos/{owner}/{repo}`。

## 当前行为

### 引用

- 引用列表默认折叠，展开后仅显示来源标题链接；移除重复回答片段、引用远程图片和联网图标。更新流式注解时保留当前展开状态。
- 网页引用短按打开链接，长按沿用链接菜单。仅 URL 合法时生成链接，不在展示时访问网页。
- 知识库引用点击后打开底部抽屉。此时才从本地数据库读取目标分块，查询同时限定 `chunkId`、`documentId` 和 `knowledgeBaseId`，避免错指另一文档或知识库。
- 抽屉显示文档标题、页码、章节、分块序号和原文字符范围，并在分块正文中高亮消息保存的精确摘录。字符范围指解析后文档文本的偏移，不等于原 PDF 排版坐标。
- 分块读取最多 65,536 个字符且不加载嵌入向量。源文档已删除时使用消息保存的摘录；匹配不上时明确展示保存摘录，不伪造高亮位置。

### 链接和媒体

- 来源图标使用本地矢量图，不调用第三方图标服务。
- Google 搜索建议保留返回的 HTML 样式与链接，但 WebView 和 CSP 都阻止网络子资源；只有用户点击导航才交给链接处理器。
- 远程聊天图片与搜索图片先读取 Coil 内存/磁盘缓存。无缓存时显示“点击加载图片”，点击后才允许联网；本地文件和 data URL 照常显示。读取缓存使用独立的 `CacheOnlyImageFetcher`，直接读取磁盘快照，不进入 HTTP 调用链；仅设置 `networkCachePolicy(DISABLED)` 不足以覆盖自定义网络工厂。未缓存不记作网络错误，避免产生误导日志。
- 正文链接、网页预览、图片预览和下载等明确的用户操作仍正常工作；用户主动发送消息调用搜索、读取网页等工具也保持原行为。

### GitHub

- 渲染时只订阅本地 Room/当前凭据内存缓存，过期缓存仍可展示。没有缓存时显示仓库名、链接和“加载仓库信息”。
- “加载仓库信息”或“刷新仓库信息”才调用 API。刷新保留 ETag、本地预算、5 秒重复点击保护及服务器限流冷却；原生卡片的语言分布按同一次主动操作补齐。
- 滚动、主题切换、样式切换、进出聊天和缓存过期均不自动刷新。Token 更换/移除会切换缓存身份并取消旧加载，身份变化不会自行触发一次新加载。
- 头像初始只读图片缓存；主动加载卡片后才允许获取头像。预览、分享、保存卡片继续使用元数据快照与头像缓存。
- 短按仍打开仓库网页；长按仍为分享、预览卡片、保存至相册。
- 抽屉的版本检查改为手动“检查更新”，不再随订阅、进入页面或时间推移访问 GitHub。主动检查仍复用已有的短期结果缓存。

## 验证

本机针对引用、知识库预览、GitHub 元数据/鉴权/缓存和版本信息的 **56 项 JVM 测试全部通过**。独立 Debug 主包与 AndroidTest 包构建成功，在 USB 连接的 vivo V2301A 上运行 **8 项真机用例，全部通过**。测试包为 `me.rerere.rikkahub.revised.citationqa`，使用合成数据、本地数据库和受控 HTTP 响应；本轮没有调用真实模型供应商。

| 检查 | 结果 |
| --- | --- |
| 网页引用 | 展开显示标题链接，不重复渲染模型回答；点击交给链接处理器 |
| 知识库引用 | 点击打开抽屉，校验分块/文档/知识库身份，显示页码、章节、字符范围并高亮摘录；文档删除后回退到保存摘录 |
| GitHub 缓存 | 过期缓存反复挂载、切换主题均不请求；点击刷新才读取元数据和语言分布 |
| 卡片交互与外观 | 原生/旧版、深浅主题、大字体、长标题、短按、长按菜单、预览、分享和保存回归通过 |
| 远程图片 | 初始无缓存时请求数为 0；点击加载请求 1 次；移除组件、清空内存缓存并重新进入后，从磁盘完成加载且请求数仍为 1 |
| 图片失败重试 | 第一次主动加载返回 503，点击重试后成功，总请求数恰为 2 |
| Markdown 图片与导出 | 先主动加载 SVG，再从缓存渲染正文、嵌套链接、列表、表格和提示块；图片可见且有正确色彩像素，导出没有新增请求 |

测试使用独立图片缓存和唯一 URL，避免上一轮缓存影响“首次加载”的判断。表格有用于测量的子组合节点，用例按各个容器的图片标签、加载状态及可见性验证，不把节点总数当作图片数量。临时 USB 保持亮屏设置已恢复。
