# 世界书使用与更新说明

## 来源绑定与向量匹配

世界书总览的“来源与绑定”入口提供全局、Persona 和助手三个分区。默认无全局或 Persona 绑定，导入标签不会自行激活。助手可关闭全局／Persona 继承；允许对话单独配置时，可在聊天扩展面板停用继承的世界书。同书多处绑定只使用一次。

向量匹配位于来源管理的全局页，默认关闭。选择向量模型后，还需在条目高级页开启“允许向量语义触发”。开启会向所选供应商发送近期对话文本和条目正文，可能产生费用。候选通过相似度与数量筛选后，仍需满足角色、概率、冷却、分组和预算。单次最多新建 32 项索引、等待 20 秒；未完成或失败时继续采用关键词，不中断主回复。静态预览和模拟不调用向量 API。

额外匹配来源由条目单独勾选，支持角色描述、性格、场景、角色／创作者备注和当前 Persona 描述。它们只作为检索文本，不自动注入；角色字段可在来源页编辑。导入条目的扫描缓冲现在以 `\x01` 分隔消息，Include Names 决定是否附加名称前缀。

在设置 → 扩展管理 → 提示词与世界书中管理世界书。点击书卡的“详情、模拟与批量操作”，可以查看助手默认引用、运行场景模拟、导出、复制和移动分类条目。

## 模式与预算

扫描范围与常驻相互独立。显式深度 0 表示不扫描任何消息，不会自动激活；NOT 条件或可匹配空串的正则也不会绕过“不扫描”。常驻条目不依赖扫描，只在已选中的世界书内作为候选，仍受预算、互斥和事件规则约束。

扫描模式可选择自定义（0–1000）、继承本书默认值、仅当前用户输入、不扫描。仅当前输入只读取最新用户消息的文本，不匹配更早历史或后续助手/工具消息。Tavern 的 null/缺省扫描深度导入为继承，显式 0 原样保留；来源没有提供默认深度时本书默认 4，可自行调整。

已由旧版本导入并被转换成 1 的条目无法可靠反推原始值，请重新导入源文件或手动修改。不要批量将所有深度 1 改成 0。

### 扫描深度范围参考

建议新手先用 **4**。以下是本应用的调参起点，不是 SillyTavern 官方强制标准，也不会自动修改已有世界书。

| 扫描深度 | 使用场景 | 注意事项 |
| --- | --- | --- |
| 0 | 不扫描聊天关键词 | 不代表常驻；常驻、递归、额外资料或向量触发需单独配置 |
| 1–2 | 即时指令、临时场景 | 旧话题不容易反复触发，但可能漏掉稍早线索 |
| 3–6 | 日常聊天、人物和地点设定 | 推荐从 4 开始，先验证命中情况 |
| 7–12 | 连续剧情、多次往返的当前任务 | 适合需要承接几条前文的场景 |
| 13–30 | 较长话题、较早线索 | 配合精确关键词和排除条件，避免已结束话题继续命中 |
| 31–100 | 有明确需要的定向回查 | 先模拟、设预算，不建议整本统一调大 |
| 101–1000 | 高级排查 | 允许输入，不推荐日常使用；长消息、复杂正则和大量条目会增加计算量及无关命中 |

单位为**消息条数**，不是 Token、字符数或对话轮数。全部消息来源中，用户和助手各算一条；仅用户／助手来源按筛选后的消息计数。例如历史依次为用户 A、助手 B、用户 C、助手 D、用户 E：全部来源、深度 4 扫描 B/C/D/E；仅用户、深度 2 扫描 C/E。若只希望匹配最新用户输入，选择“仅当前用户输入”，不要认为它总与深度 1 等价。

调整时从 4 开始，只有确认线索落在扫描范围之外，才逐步尝试 8、12；旧话题反复触发时先缩小范围或收紧关键词。预算不足、概率未命中、未绑定等原因不会因增加深度而解决。持续性事件可使用“持续激活”，不必无限扩大扫描。

扩大扫描不会直接把全部扫描历史注入模型，但可能采用更多条目，间接增加上下文占用。推荐范围只用于聊天关键词扫描；“最少激活”可扩大回溯，递归、额外匹配来源、向量查询另有规则，实际还受可用上下文长度限制。本书默认值只影响选择“继承本书默认”的条目，不会覆盖条目自定义深度或其他扫描模式。

应用内入口：“世界书帮助与教程”第 4 节；世界书“设置”和条目“触发”页也有默认折叠的同名范围参考。

兼容性依据：[SillyTavern 官方 world-info.js](https://github.com/SillyTavern/SillyTavern/blob/release/public/scripts/world-info.js)，`WorldInfoBuffer.get` 对零深度返回空串，缺省使用默认深度；常驻在关键词匹配之前独立处理。

- 已有原生世界书保持原行为：普通模式使用普通关键词，娱乐模式额外使用组合表达式、概率、持续与冷却、互斥组及单书预算。新导入的 SillyTavern/V2/V3 条目带有来源标记，其兼容规则在两种界面模式下都生效；含此类条目的书也保留单书预算约束。
- 两种模式均支持扫描来源选择和跨世界书总 Token 预算。
- 跨书总预算按照世界书列表顺序分配。书内优先级越高越优先保留；SillyTavern 来源的常驻条目先参与预算选择。0 表示不限。聊天预算按变量展开后的世界书正文估算，不等于供应商最终计费 Token 数，也不含后续模板、协议及其他上下文开销。
- 插入顺序与预算优先级分开：显式插入顺序越小越靠前；留空沿用原生的优先级降序。导入分别读取 `insertion_order` / `order` 和 `priority`；没有独立优先级时，以来源顺序作为预算选择的兼容回退。
- 启用表达式后会替代普通关键词条件；可视化条件辅助会生成表达式，应用前可检查文本。
- 引号内的 AND、OR、NOT 是普通关键词。引号和反斜杠可使用转义。
- 导入条目支持普通词与 `/pattern/flags` 混用，目前支持 `g/i/m/s/u`；`y/d/v` 及未知标志会明确显示兼容性诊断，不会静默降级。匹配基于 Android/Java 正则，不能保证所有 JavaScript 正则语法完全等价。`g` 在布尔匹配中作为无状态标记，不保留跨请求游标。导入旧版以空格或逗号拼接的关键词字符串时，会保留引号短语及正则字面量（包括其中的斜杠、空格和逗号），避免误拆分。
- 可开启完整词匹配，防止英文 `cat` 命中 `catalog`。中文、日文通常应关闭。关键词可使用应用已有占位符，例如 `{{char}}`；不支持的 SillyTavern 专用宏不会伪装成已执行。
- 正则共用一次评估的字符读取上限，超过上限会停止匹配并显示错误；可缩小扫描范围或简化表达式。规则指纹和编译结果使用有界缓存，避免每次重复处理来源元数据。
- SillyTavern 的递归字段会随条目和世界书保存。启用本书“递归扫描”后，首轮扫描聊天内容，后续扫描已选条目的正文；`maxRecursionSteps=0` 使用安全上限，避免循环；`preventRecursion` 阻止该条目继续触发，`excludeRecursion` 使条目不能在递归轮激活，`delayUntilRecursion` 只在递归轮激活，`recursionLevel` 可限定层级。已激活 ID 和预算共同防止重复及无限递归。`includeNames` 会在扫描缓冲中加入实际用户昵称和助手名称；`minActivations` 会扩大首轮回溯范围，`maxScanDepth` 限制扩大后的最大深度；`useGroupScoring` 按命中关键词数量筛选互斥组候选，再应用权重或优先级。
- 条目可限制生成触发类型（`normal`、`continue`、`impersonate`、`swipe`、`regenerate`、`quiet`）；未填写时对所有类型生效。角色过滤支持名称和助手标签，并可切换排除模式。`ignoreBudget` 条目不占用本书或跨书预算，应谨慎使用。

## 事件生命周期

- 原生默认按用户轮次计数，持续轮数包含首次激活的一轮；新导入默认按消息计数，用户消息和助手消息分别计数。可在条目高级设置切换单位，切换后旧运行状态会失效。
- 按消息计数时，持续 0 表示不延续。设触发时历史消息数为 M，持续 N 的结束边界为 M+N（边界不再持续），随后进入冷却；例如 M=1、持续 3、冷却 2，在消息数 2、3 时持续，4、5 时冷却，6 起可再次触发。模型内部工具往返不额外推进对话历史计数。
- 延迟激活独立使用历史消息数：未达到设定数量时不激活。按消息计数的重新生成会重新检查条件，不把同一次触发误判为冷却拒绝。
- 概率采用对话种子、条目和轮次，重试同一轮可复现，不同对话独立。
- 只有成功完成生成才提交新的激活和冷却状态。失败或取消仍可查看诊断，但不提交本次状态。
- 修改规则、编辑最初触发的用户消息或回到触发之前的分支，会使不适用的旧激活状态失效。
- 同书同互斥组最多采用一个条目，优先保留持续激活中的条目。没有持续条目时：权重全为 0 按优先级；存在正权重则按权重随机，0 权重不参与。
- 允许对话级提示词配置时，在聊天扩展菜单取消世界书，只关闭当前对话，不改变助手默认设置。再次选中可恢复。

## 编辑、导入和恢复

原生导出（`version: 1`、`type: lorebook`、`data`）与 Tavern 文件分别解析。原生文件中的 `top_of_chat`、`bottom_of_chat` 等位置原样保留，不套用 Tavern 数字位置映射。旧版未保存扫描模式字段时沿用自定义数值深度，0 和常驻设置均保留；不会根据名称或另一份世界书自动补写互斥组等缺失设置。

原生导入重新生成书和条目 ID，并保留停用条目；未识别的版本或损坏字段会报告具体错误，不降级为其他格式。新版扫描模式、默认深度、预算和互斥配置均支持导出再导入。导入生成的是新副本，合并或替换已有书仍需在预览中确认。

- 编辑条目时，正文、触发条件和高级设置分组展示。数字可清空重填，保存前检查范围和表达式错误；与当前设置无关的数字输入不额外阻塞保存。
- 世界书和条目草稿保存在页面 ViewModel 中，避免旋转屏幕丢失，也避免将大型世界书放入 Activity 状态 Bundle。离开未保存的编辑器会确认是否放弃；保存期间防止重复提交，落盘成功后才关闭，失败保留草稿并显示原因。此草稿不承诺跨应用进程终止保存。
- 并发编辑不同条目会合并；同一字段或条目已被其他操作修改、删除时会报告冲突，避免静默覆盖。发生保存冲突或失败时，可将保留的草稿另存为新世界书。提示词扩展使用独立的持久化更新路径，写入失败不会提前把内存中的条目当作已保存。
- 编辑书时可按名称、内容或条件搜索，按分类筛选，批量启停及修改分类。删除条目后可撤销。
- 每本书保留最近 10 个已保存的旧版本，恢复后需要保存。历史仅本地保留，导出默认只包含当前版本。
- 独立世界书与角色卡内嵌世界书共用转换，但区分 SillyTavern、Character Card V2 与 V3 来源。支持独立 `lorebook_v3` 包装，也可从 V2/V3 角色卡读取附带世界书。
- 未知字段及 `extensions` 保留在来源元数据中，并随原生导出/再次导入保留；保留不等于执行。递归、分组评分和 Outlet 等已映射字段按本地兼容规则执行；向量触发需额外启用并配置模型；多组与忽略预算有本地运行实现，Automation ID 仍仅保留并提示。缺关键词或空正文的对象条目会保留并提示，避免丢失暂未支持的设置。
- SillyTavern 数字位置 2/3（作者注释）映射到系统提示词之后，5/6（示例消息）映射到聊天开头并保留来源语义；7 为 Outlet，必须填写名称并通过 `{{outlet::名称}}` 宏显式拉取，不会自动插入。未知位置才会暂停条目。支持深度 0 插到提示末尾，以及独立 system/user/assistant 消息角色；多个深度共用未插入世界书的消息快照，避免锚点随插入漂移。
- V3 `use_regex` 导入时忽略 `constant` 和辅助关键词；关闭正则时，带斜杠的关键词也按字面匹配。尚未支持的 `@@` 装饰器保留在编辑内容中，但不会作为普通正文注入模型。
- 导入提供另存、合并、替换。同名条目逐项选择保留原项、使用导入内容（保留原 ID）或保留两者（新 ID）；默认不覆盖原项。多条同名导致对应关系不唯一时，不允许自动替换，默认保留两者。替换整本需要额外确认；目标发生变化时需刷新预览再核对。
- 工具协议兼容：`ask_user` 最终仍要求 `questions` 数组；对 Gemini 的 `functionCall.args`、OpenAI 兼容网关的字符串化 arguments 及 Anthropic 的传输包装只解包 JSON 对象，不把单个 `question` 或非法字段自动改写成有效请求。
- 合并、复制或移动条目时，将“继承来源扫描深度”固化为显式深度，包括 0，避免套用目标书的另一个默认值。目标书的预算等设置仍按目标书执行。
- 独立世界书及角色卡 JSON 最大 16 MiB，单次最多 10000 个条目；PNG 角色卡的解码元数据也有限制。

## 场景模拟与诊断

模拟器复用聊天评估器，无须模型调用，不写入真实对话。可以输入此前助手回复和本轮用户消息，逐轮推进，验证扫描来源、概率、持续、冷却、互斥及预算。可同时模拟其他世界书，观察总预算分配。

诊断显示匹配词项、采用状态、位置、估算 Token、持续与冷却剩余轮数，以及实际注入正文。模拟预览止于世界书注入阶段，不代表后续供应商协议转换、其他提示词模板及上下文压缩的最终请求。

独立模拟没有选择实际助手的变量值，含占位符的预算以聊天诊断为准。诊断中的计数标明“轮”或“条消息”；位置待映射、延迟尚未到期、正则超出计算上限等原因也会显示。
