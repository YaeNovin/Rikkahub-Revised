# 链接菜单与聊天模型生图：第一阶段

开发状态：2026-09-23，尚未发布。原有手动聊天生图和独立图片页面继续保留。

## 链接操作

- 普通点击沿用 Custom Tabs；长按普通链接、Markdown/HTML 超链接、搜索引用、仓库卡片和图片链接可打开操作菜单。
- 菜单提供打开、复制链接、复制链接文字、分享。图片链接还保留原有图片预览入口。
- 网页链接可选择“让模型总结网页”或“围绕链接提问”。操作追加到现有草稿，用户确认发送后才交给聊天模型；不会在长按或打开菜单时发起模型请求。
- 总结指令明确要求无法读取时说明原因。要读取网页，仍需为助手启用适当的联网工具；本阶段没有另建网页抓取和知识库导入流程。
- 原生文字选择继续保留；从链接开始滑动应正常滚动，不应误开链接。

2026-11-20 补充修复了短按/长按触点争抢和长搜索输出截断后无法解析引用的问题，链接菜单增加应用内网页预览。实现、设备验证及 GitHub 卡片后续方案见[链接交互审阅](github-cards-and-link-interactions-20261120.md)。

## 开启与使用

在助手的本地工具设置，或聊天原有图片参数面板中，开启“允许聊天模型调用生图”。默认关闭，需要配置可用图片模型，聊天模型需要支持工具调用。原有面板新增“模型自行调用（无需逐次确认）”，默认关闭；开启后可能产生费用，模型可根据当前需求自行发起生图。

### 工具声明和未启用状态

- 对外接口保持 `generate_image`（不额外声明 `generate_images` 别名，保留历史调用兼容性）。与其他客户端工具共用 `Tool`、`InputSchema.Obj`、工具列表和批准/执行/结果回传流程，唯一模型入参为 `prompt`，长度为 1–12000 字符；参数仍由用户控制。
- 仅在有当前对话、助手启用该工具、聊天模型支持工具调用、选中的聊天生图模型及供应商已启用且能力规则支持生图时，才注入生图工具声明。只配置独立生图页面的模型不会替代聊天的模型选择。
- `inspect_generated_image` 还要求聊天模型具有图像输入能力；未启用生图时也不注入此查看接口，不再对所有视觉模型默认开放。
- 未启用时，`get_session_capabilities` 仅返回 `image_generation: {"enabled": false, "status": "disabled"}`（未启用），`availableTools` 不列出生图/查看接口，省略调用规则和参数权限等细节。启用时返回 `tool: "generate_image"` 及相应规则。
- 不为未启用的生图自动添加 `ask_user`；用户单独开启的通用 `ask_user` 保留，描述、Schema 和能力示例均不附加生图选项。模型自己生成的自由文本问题不属于静态接口声明，不能仅靠隐藏声明保证模型永不提及生图。
- 按需查看提示也依据本次实际工具列表生成。此规则控制新请求中的接口声明，不删除历史生图消息、附件或已确认任务的恢复记录。

### 2026-09-24：修复旧能力查询覆盖当前状态

QA 中确认过一种矛盾回答：早先调用 `get_session_capabilities` 时生图未启用，之后用户启用生图并继续同一对话；模型看到当前工具定义，却仍引用历史工具结果中的 `enabled=false`，没有再次调用查询接口。

- 发送普通请求和断线续答前，仅在请求副本中重新计算历史能力查询结果。结果标注 `snapshot_scope=current_request`，以该请求实际工具列表与配置为准。
- 原始对话、旧工具调用/结果、调用 ID、协议元数据、用户回答与批准状态不写回或删除；历史记录仍保留当时的真实情况。
- 只刷新应用内的只读能力查询，不执行生图、看图、问答表单或其他工具。新对话没有旧能力查询时，不增加刷新操作或额外系统提示。
- 用户关闭生图、移除图片模型或切换为不支持图像输入的聊天模型时，也刷新为对应的当前状态。未配置时继续隐藏生图工具声明、保留精简的“未启用”，不放宽手动参数约束。
- 能力查询定义与实际工具清单统一绑定，重复的旧查询定义不能覆盖当前定义。接口不可用或刷新失败时标记历史结果不可用于当前状态判断，不悄悄回退到过期的 enabled/disabled 值。
- 新增 `SessionCapabilitiesContextTest` 覆盖先关闭后开启、反向关闭/移除配置、文字模型降级、请求重建与续答、原始历史/协议元数据保留、失败/取消、详情选项、同参数查询复用及重复定义替换。

这是请求上下文修复，不是让应用替用户开启生图，也不保证任意模型永远不误述能力。实际模型答复需要更新测试包后验证；本次修复不触发收费模型请求。

验证结果：应用 Kotlin 编译通过；8 个定向测试类共 54 项 JVM 测试通过，其中新增能力上下文回归 10 项，`git diff --check` 通过。使用连接设备对该测试对话做了只读核对，确认旧能力查询之后的追问未重新查询；当前助手已启用生图并配置聊天图片模型。没有修改设备设置、对话数据或安装包，也未调用真实模型。
- 上述开关针对应用注册的外部生图工具，不改变原有手动生图或供应商原生多模态输出配置。

1. 用户提出生图需求，聊天模型通过 `generate_image` 提出候选提示词。
2. 应用创建与对话、用户请求、回答和工具调用绑定的持久任务，展示专用确认卡。
3. 逐次确认模式下，用户选择完整原文、模型建议或手动修改。模型、数量和全部基础/高级选项统一由原来的手动生图面板设置；确认卡只链接回该入口，不再维护另一套参数。
4. 点击“确认并生成”后固定本次提示词、模型、供应商配置指纹和参数。选择默认值、展开面板或通用工具批准都不能代替该确认。
5. 生成结果先保存为附件，再作为工具结果交回聊天模型，继续本轮文字回复。

自行调用模式下，应用以用户当前手动设置创建不可变请求快照并批准，随后等待图片，再继续文字回复。缺少当前会话的手动选项或配置无法通过校验时退回确认卡。参数仍为会话临时选项，重新进入会话可能恢复默认值；已批准任务的快照不受影响。

开启生图工具也会提供 `ask_user` 用于澄清意图，不强制每次提问。如果同一批响应同时发出 `ask_user` 和 `generate_image`，生图调用会被推迟且不占用生图任务次数；模型收到回答后应重新组织提示词再发起。拒绝、取消、过期或 confirm=false 不会授权自行生图。表单答案只说明意图，不能修改尺寸、数量等参数，也不能取代逐次确认模式的确认卡。

## 等待与参数规则

| 阶段 | 行为 |
| --- | --- |
| 确认前 | 确认卡编辑提示词；其他选项统一在手动生图面板修改，手动生图和之后的工具调用共用这些设置 |
| 已确认但等待其他问题 | 显示“已确认，等待执行”；其他待审批工具处理完后开始，可取消尚未执行的生图 |
| 正在生成 | 参数锁定，复用手动生图的 skeleton/shimmer；可浏览、切换对话、编辑草稿；本轮续答等待图片返回，不提前标记回答完成 |
| 停止等待 | 取消本地执行；供应商可能仍在处理或计费，不承诺远端取消或退款 |
| 图片成功 | 复用手动生图的固有宽高比、最大 320dp 展示和缩放预览；展示参数快照；续答重试复用已有结果，不重新生图 |
| 部分成功/结果未知 | 保留已保存图片，说明失败或中断；需要新图片时发送新的请求并重新确认 |

本阶段每个用户消息最多提出一次工具生图任务，未设置数量时默认一张，每次最多四张，并遵守模型自身更小的限制。原有手动生图不受此工具次数规则影响。

高级参数复用 `ImageGenerationSettingsBottomSheet` 和 `ImageGenerationRequestState`，包括模型支持的质量、格式、背景、压缩、分辨率、种子、步数、引导强度、负面提示词及供应商专属选项。参数约束在界面及提交时再次校验。

模型自定义请求体可能覆盖提示词或数量，因此本阶段工具生图不接受开启自定义请求体覆盖项的图片模型；确认时会要求改选合适模型。自定义请求头保留，原有手动生图仍按原配置工作。

## 持久化和恢复

- Room 43 → 44 自动迁移新增 `chat_image_tool_task` 表，保留旧数据。
- 付费请求前先原子地领取已批准任务；同时确认、重复恢复或文字续答重试不会再次领取已完成任务。
- 每张最终图片落盘后保存到任务记录；预览帧不作为最终图片重复保存。
- 进程终止留下的执行中任务变为“结果未知”，不会自动重复 POST。常驻服务不等于远端恰好执行一次。
- 回写检查原对话和原回答；目标被删除或切换时停止回写，不以生图结果重建已删除对话。
- 生图前先等待所属消息落盘，生图后持久化工具结果再发起续答；不是仅向带缓冲的消息流发送更新。数据库检查点失败时不启动付费请求。
- 所有聊天模型默认接收文字状态，图片仍在对话中展示。仅视觉模型获得 `inspect_generated_image(task_id)`，可自行决定是否读取已保存的图片；任务必须属于当前对话分支，不接受任意 URL 或文件路径。
- 图片过滤在输入转换器之前进行，避免被动 OCR 等路径绕过按需查看。切换到非多模态模型后，历史查看工具中的图片也不再发送。生图参数快照不转发给聊天模型。
- 生图等待沿用已有会话 Job 和后台生成保护；等待 `ask_user` 则保存交互状态，回答后重新续接，不维持空闲网络连接。网络故障、供应商超时或系统杀进程仍可能中断；这不等于远端取消，不通过重发不确定的生图请求掩盖失败。
- 保留供应商工具元数据，包括 Google 的 thought signature 和 function call ID。

第一阶段为 Android 确认界面、文生图流程。参考图/图像编辑、多设备同步、Web 专用确认卡及供应商异步任务查询不在本阶段实现范围内。
