# Web 后台访问超时：定位、修正与真机验证

## 根因与必要系统设置

本机 vivo V2301A / Android 16 的“智能控制后台耗电”会在应用退到后台数秒后冻结整个进程。WebServerService 仍显示 `isForeground=true`，Android ActivityManager 的通用冻结标志甚至仍为 false，但厂商扩展显示 `isFrozen=true`，全部线程停在 `do_freezer_trap`。

因此静态网页、会话分页、设置、助手切换和 SSE 同时失效，截图中的请求超时并非单独的历史消息接口错误。已检查网络策略：测试 UID 的有效网络阻止状态为 NONE。

**该机必须将实际使用的应用设为：系统应用信息 → 电量 → 后台耗电管理 → 允许后台耗电。**“智能控制后台耗电”仍可能冻结前台服务。普通 Android 电池优化豁免与此厂商选项不是一回事。

做过以下对照，未将无效手段宣称为解决方案：

| 条件 | 实测结果 |
| --- | --- |
| 原版本 + 厂商智能控制 | 前台 200，退到桌面数秒后静态页面与 API 均超时，熄屏同样失败 |
| 添加 Web CPU 唤醒锁 + 厂商智能控制 | 仍失败；系统将锁标记为 `DISABLED ... mIsFrozen` |
| 添加 Android device-idle 豁免 | 仍失败；测试后撤销该临时豁免 |
| 厂商“允许后台耗电” + 修正版 | 后台与熄屏访问恢复，线程恢复为正常 epoll/futex 等等待 |

应用不能静默覆盖厂商的后台权限，因此修正包括服务运行保护、明确的系统设置入口和准确诊断，不承诺只安装新版就能绕过此限制。

## 代码改动

- WebServerService 在启动/运行期间持有独立的 PARTIAL_WAKE_LOCK，90 秒租约、每 60 秒续期。它不依赖聊天生成任务或 Activity 可见性，停止、启动失败和销毁时释放。启用 Web 服务会增加耗电，设置页明确说明。
- 服务使用 START_STICKY；系统重建时只根据已保存的 Web 开关恢复。显式停止先持久化关闭状态，再停止服务器，避免停止观察器先取消持久化任务。服务销毁时清理仍运行的监听器。
- 前台通知立即展示；启动失败也结束前台服务，避免留下“正在启动”的无效通知和唤醒锁。
- 手机 Web 设置新增后台访问说明、Android 电池优化/后台限制状态及应用信息入口。vivo/iQOO 显示实测有效的菜单路径。返回设置页时刷新状态，不把 Android 豁免误报为厂商放行。
- Web 安全性页显示相同的后台状态和厂商指引。超时与认证错误分开：超时提示检查手机后台策略，401 仍走原有登录流程；未延长网络超时来掩盖问题。

## 验证范围

- TypeScript 检查、生产 Web 构建、Debug APK 构建通过。
- Node 网络/重连测试 9 项、Edge 生产网页回归 3 项通过。Lint 0 错误、7 个既有警告。
- JVM：WebConfigurationTest 10 项、WebSettingsDtoTest 2 项、WebAuthSessionsTest 4 项通过。
- 独立 QA 包：`me.rerere.rikkahub.revised.websettingsqa`。没有覆盖用户的正式应用或读取其会话。
- USB 及真实 Wi-Fi 地址 `192.168.1.227:8080`：手机退到桌面和熄屏后，通过电脑 Edge 中的实际 APK WebUI 发送消息、接收流式回复、刷新会话历史；后台保存设置、切换助手、接收设置 SSE 均通过。
- 局域网静置回归：桌面后台、熄屏各不发送请求 60 秒，随后静态页面、会话分页和设置接口全部返回 200；全程 27–581ms，无超时。验证跨过唤醒锁续期周期，非只靠持续请求保活。证据在 `lan-idle/`。
- 消息测试只有模型端使用电脑本地模拟 HTTP/SSE 服务；Android ChatService、数据库、Web API 和生产 WebUI 都是真实路径。没有调用外部付费模型。不能据此宣称所有外部供应商的网络或鉴权行为都已验证。
- 一次 USB 脚本清理误把成功的 204 删除响应当成 JSON 解码，导致测试程序报错；已修正测试助手，后续局域网完整流程及清理全部通过。
- 最终 APK 再次通过 `final-lan-flow/` 验证，包括等待历史列表完成加载后截图。测试结束恢复仅本机监听偏好、原厂商“智能控制”策略和无 Android 电池豁免的状态；停止 Web 服务，确认没有活动的 Web 唤醒锁，移除 18080 转发和 18090 反向转发。正式应用配置未改动。
- 本地证据：`docs/local/web-background-2026-10-06/` 下的 `before/`、`guard/`、`whitelist/`、`oem-allowed/`、`final-flow/`、`lan-flow/` 和构建日志。保留失败对照，不以成功结果覆盖失败证据。

## 复现与使用

测试入口见 `web-ui/tests/README.md`。`device-web-background.ts` 测试静态页面、会话分页和设置接口，并抓取后台线程与服务状态；`device-web-background-flow.ts` 验证实际网页消息流程及设置同步，finally 恢复配置并删除临时会话。

此修正不承诺在用户强行停止应用、厂商继续冻结进程、网络断开或系统极端资源回收时保持服务。厂商后台选项必须对**实际安装并使用的包**设置，QA 包的设置不会自动作用于正式包。
