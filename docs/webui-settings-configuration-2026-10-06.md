## 保存与访问规则

- 新增 `/api/settings/manage` 管理接口，使用分组 revision 检测并发修改；冲突返回 409。编辑中的草稿不会被 SSE 覆盖，离开页面提示未保存修改。
- 保存响应返回更新锁内捕获的本次配置，避免保存后再次读取异步 live flow 时返回其他快照。
- 敏感管理要求启用密码认证且提供有效 Bearer，Cookie-only 和未启用认证的访问不能管理凭据。
- 响应采用递归字段白名单。密钥、请求头/请求体、脚本和覆盖配置只写不回显；null 保留，明确的空值清除。OAuth 状态不从浏览器写入。
- 排除的图片/视频模型和图片建议配置继续保留；新功能不会通过设置事件流暴露管理凭据。
- SSE 请求同时接受事件流与 JSON，使真实 Ktor 服务器的 401 认证错误能正常触发登录窗口，避免因内容协商变为 406。

## 尚未覆盖的边界

- 本轮真机验收是桌面浏览器经 USB 访问手机，窄屏是浏览器 viewport；不等同于手机浏览器、Wi-Fi 局域网或公网 HTTPS 的端到端验收。
- 未请求真实付费模型生成、外部搜索或外部 MCP 服务；测试 MCP 保持禁用。模型列表获取入口已接通原生逻辑，但未验证每种外部供应商的可用性。
- OAuth、Android 通知/局域网授权、首次启用密码和停止服务后的启动仍需手机操作。HTTPS 仍由反向代理提供。
- Skills 支持 SKILL.md 正文管理，未新增整包附件上传或网页 shell。高级凭据只写设计不提供明文读回。
- 此设置落地阶段未处理后台 Web 服务停顿；后续已单独定位与修正，见 [后台访问报告](web-background-access-fix-2026-10-06.md)。
- 此前部分全局聊天建议显示/插入选项尚未完全被 Web 聊天界面消费；本轮完成原生配置写回，不宣称全部显示行为已与原生一致。助手温度、Top P、最大输出等仍从手机调整。
