# 全屏预览与返回位置审查

日期：2026-09-09。根据用户截图和多次返回位置丢失反馈，检索 app 全部预览入口、导航、滚动调用、消息加载、原生 WebView 与 HTML/CSS 的尺寸约束。

## 前几轮修复的缺口

1. Mermaid、通用代码块、整条消息预览都通过 `rememberWebPreviewLauncher` 导航到 `Screen.WebView`。Navigation 3 会移除聊天内容的组合，再返回时恢复；仅保存 LazyList 索引/偏移并不保留 Markdown/WebView 的测量高度。
2. 原恢复逻辑在目标消息是占位高度时反复尝试滚动，最初只有 2.5 秒、后来增加到 10 秒。恢复后还存在异步图形/消息状态变化，固定等待时间无法证明位置稳定。
3. ChatPage 以前以 Loading/Ready 切换整个列表；最新加载动画修复是在 `174218` 包安装之后编写，测试手机上的该版本并不包含它。此问题不能仅靠改变转场时长处理。
4. 全屏页仍有占高度的 Scaffold TopBar，HTML 中移动的只是 SVG/Canvas。ECharts、Mermaid、通用渲染器的祖先容器可能有 overflow 裁剪，导致“窗口内移动”，而非屏幕画布移动。
5. 之前浏览器测试只用了独立 SVG，未覆盖受限的嵌套渲染容器；Android 位置恢复用例只编译，没有成功执行。此前结论的真机证据不足。

## 本次实现

- 聊天页拥有 `ChatWebPreviewHost`，所有聊天内预览入口优先调用该覆盖层；不修改导航栈，不销毁原列表，也不启动旧的恢复位置循环。其他页面仍保留原导航入口。
- 预览显示期间禁用聊天的自动跟随和键盘滚动补偿。关闭时销毁预览 WebView，底下的列表、消息选择/展开状态及像素偏移自然保留。
- 覆盖层使用 Android 全窗口 Dialog（无平台默认宽度，无系统窗口内边距），隐藏系统栏；关闭、重置和诊断按钮悬浮于画布，不占用单独标题栏高度。
- HTML 场景整体平移/缩放，固定图表尺寸继续由库管理；移除祖先对场景的裁剪，空白处也能拖动。地图继续使用 Leaflet 自身手势。视频、iframe 等内部内容的独立交互仍有各自边界。
- 图形卡片统一为顶部语言/源码下载/复制/源码切换，中部预览，底部预览及图像保存。保持现有 richContentColors 的背景、边框、透明度适配。普通代码块不使用图形底部操作。
- Mermaid 保留原 SVG 导出。其他渲染器保存当前预览区域为 PNG，限制 400 万像素，通过系统文件选择器保存；这不是超长图形完整页面导出。

## 验证边界

- `verify-fullscreen-pan.cjs` 检查居中、拖动、双指模拟、复位以及从空白区域将图形移出原矩形后仍可见。
- `ChatWebPreviewHostTest` 使用真实 Dialog、WebView、启动器和长列表，连续三次检查导航栈不变、列表实例相同、消息组合未销毁及偏移保持。已纳入 Android 测试编译。
- 设备授权连接正常，但独立 Debug 包两次安装均返回 `INSTALL_FAILED_ABORTED: User rejected permissions`，因此该 Android 用例本轮未实际运行，当前 QA 数据及版本未改动。
- 最终 QA Kotlin 与 Android 回归代码编译通过；32 项 JVM 测试通过；19 个真实图形浏览器场景及全屏拖动专项通过。浏览器交互结果不替代 Android 系统窗口、原生触摸和导航真机测试。
