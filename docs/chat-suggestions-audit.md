# 聊天建议检查与修复

检查范围：默认模型与提示词设置、后台建议生成、会话状态、存储兼容、聊天建议布局和点击操作。2026-09-10。

## 本轮确认的问题

| 问题 | 修复方式 |
| --- | --- |
| 多次刷新会重复请求；隐藏建议后旧请求仍在执行 | 每个会话只保留一个有效请求，隐藏或开始新一轮时取消旧请求，过期回调不能覆盖新状态 |
| 手动刷新未持有完整生命周期的会话引用，切页后可能受空闲会话清理影响 | 整个生成过程持有会话引用，并从当前已加载状态获取源消息 |
| 只绑定回答 ID，编辑相同 ID 的回答后旧建议仍可出现 | 新建议绑定最近选中消息内容的摘要标识；保存与展示均校验，标题与 Token 元数据变化不使建议失效 |
| 网页接口直接下发原始缓存，未跟随手机端的过期过滤 | 网页 DTO 复用同一来源校验，生成期间不下发旧建议，建议变化触发完整会话更新 |
| 末尾新增用户消息、回答被中断或工具仍等待确认时也可能生成建议 | 仅在当前末尾是可用的助手文本回答且工具执行完成时生成、展示建议 |
| 延迟启动的自动任务可能读取下一轮回答，长回答只截取开头导致结论缺失 | 启动时校验来源快照，拒绝对正在输出的回答生成建议；上下文同时保留开头和结尾，附件仅提供类型与数量提示 |
| 取消会作为生成失败显示；首次失败后没有直接重试入口 | 正常传播取消，忽略过期错误；显示紧凑的生成状态和失败重试入口 |
| 建议能力与会话记忆模式、主模型工具能力不一致 | 统一根据当前会话有效配置筛选；支持仅 RAG 和仅提取模式，识别模型自带搜索；生成时排除未启用的知识库 |
| 无效 JSON、布尔值、数字可能成为建议文字 | 结构化返回先验证类型，失败时不把原始 JSON 拆成按钮；兼容正常列表文本和字符串数组 |
| 一条损坏记录导致整组读取失败，重复 ID 可影响 Compose 列表 | 逐项恢复，未知动作降为文字插入，过滤无效条目并修复重复 ID |
| 快捷消息还没保存就显示成功，协程执行时可能读取到其他助手 | 点击时固定目标助手，等待保存成功后提示，失败显示错误；设置修改使用最新快照 |
| 从建议创建分支未携带该建议内容 | 分支创建成功后按追加/替换设置填入草稿，不自动发送 |
| 双行建议触摸区拥挤、面板按钮小屏溢出、浮动建议遮挡消息 | 增加双行间距和触摸高度，操作按钮换行，列表底部按建议实际高度留白；卡片使用现有富内容表面配色 |

旧版本没有内容摘要标识的缓存仍兼容读取；无法从旧缓存推断其生成时的完整上下文。新生成的建议才具备完整内容失效检查。

建议中的工具类动作仍是用户可编辑的输入草稿，不强制模型调用工具，也不绕过工具本身的审批。模型自带能力及本地启用状态可以预先检查，第三方服务是否在线仍由实际请求决定。
