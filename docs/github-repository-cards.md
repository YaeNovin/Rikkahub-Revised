# GitHub 仓库卡片

聊天中 AI 回复完成后，Markdown 渲染器将符合条件的仓库主页链接在原位置显示为紧凑卡片，不再统一追加到消息末尾。裸链接和命名链接均适用；行内、列表和表格中的周边文字及格式保留。消息原文不变，不把远程仓库内容加入模型上下文。卡片显示仓库名、简介、Star、Fork、语言、许可证及归档/派生状态，采用当前富内容的主题颜色、边框与透明度；点击打开 GitHub。

## 识别范围

- 接受 `http(s)://github.com/{owner}/{repo}`（含 `www` 和单个尾部斜杠）。大小写统一缓存；链接在句子、列表、引用、表格或混合 HTML 中均通过现有 Markdown/HTML 解析器识别。
- 不将 `/tree`、`/blob`、`/releases`、`/actions`、`/wiki` 等子路径，用户主页、Topics、组织管理页、查询参数或锚点转换成仓库卡片。单个 Issue/PR 也保留原链接，尚未实现它们的子类型卡片。
- 代码块、行内代码、图片、图片徽章的跳转链接、SVG 内链接不触发；不根据正则猜测代码字符串。每段回复正文按出现顺序最多转换 6 处，其他链接仍可正常点击。同一仓库可以在不同位置显示，但网络与缓存按规范仓库名去重。
- 仅 AI 正文启用，用户消息、工具返回、提示词编辑器不自动发起元数据请求。流式输出期间不请求，卡片进入可见区域停留 350ms 且页面位于前台后才刷新；屏幕外、后台、预览遮挡和导出时不发起新网络请求。

## 官方 REST API 与 Room 缓存

- `GET https://api.github.com/repos/{owner}/{repo}`，固定 `Accept: application/vnd.github+json`、`X-GitHub-Api-Version: 2026-03-10` 及 User-Agent。独立无鉴权 OkHttp 客户端，不继承模型供应商的 Key、请求拦截器或 Cookie；不请求 README、头像或仓库文件。
- Room 40→41 新增 `github_repository_cache` 和 `github_api_cache_state`，原有业务表不变。缓存仅存公开仓库显示字段、ETag、时间和失败状态；缓存最多 500 条。
- 缓存 30 分钟内直接使用；过期时先显示旧数据，使用 ETag / If-None-Match 条件更新，304 延长有效期。无许可证、描述或语言时可以正常显示。
- 请求串行执行，进入队列后重新查缓存，相同仓库并发请求只消耗一次。失败默认缓存 5 分钟；404/410 缓存 30 分钟并停止显示旧元数据，卡片仍可打开网页。网络失败可使用过期缓存，标注“显示本地缓存”。失败后提供手动重试，至少间隔 5 秒；手动重试可跳过失败缓存，但不能绕过服务端冷却或本地小时预算。
- 遇到 429、`X-RateLimit-Remaining: 0`，或携带限流证据的 403，将服务端重试时间保存到 Room，对所有仓库暂停请求。普通权限拒绝 403 不再阻塞其他仓库。遵循 Retry-After 和 X-RateLimit-Reset；限流未给重试时间时至少等待 1 分钟，不自动循环重试。
- 本地额外限制每小时最多 50 次请求，为共享出口 IP 的其他请求留余量。GitHub 的额度仍按出口 IP 共享，本地缓存无法阻止其他应用使用该额度。**未鉴权的 304 不保证免额度**，本地预算照常计数。
- 每次网络调用最长 20 秒，保留 OkHttp 的连接故障恢复，元数据响应上限 512 KiB，可随页面销毁取消。仓库重命名仅跟随 HTTPS `api.github.com` 下 `/repos/{owner}/{repo}` 或 `/repositories/{id}` 的合法重定向，总计最多 3 次请求，每次均计入本地预算；拒绝其他主机、凭据、查询参数和非仓库 API 路径。
- 卡片显示 DNS、超时、TLS、HTTP 状态码、限流及响应解析失败的分类提示。真实请求失败写入软件日志 `GITHUB_CARD`，包含公开仓库标识、接口主机、状态码/错误类别和重试时间，不记录密钥或原始响应正文。
- 同仓库卡片订阅 Room 更新，一处重试成功后其他卡片同步刷新；导出仅等待读取本地缓存，不发起新网络请求。

## 验证

- 本轮 QA Kotlin 编译、29 项相关 JVM 测试通过；V2301A / Android 16 上 `GitHubCardNetworkProbeTest` 通过，验证真实公开 API、临时 Room 缓存读写与更新订阅，仅产生一次 API 请求。使用独立 debug 包，未覆盖常用 QA 包，也未读取用户聊天数据库。原位卡片的完整原生交互仍待用户复测。
- `GitHubRepositoryTest`：严格 URL 分类、无鉴权头、空字段、缓存及仓库实例重建、20 路重复请求、ETag/304、限流重启冷却、离线旧数据、404、预算上限、大小限制、取消与 Retry-After。
- 新增网络失败后手动重试、不可绕过冷却、普通 403 不影响其他仓库、官方重命名跳转及危险跳转拒绝的回归。
- `GitHubRepositoryLinksTest`：裸链、命名链接、引用式链接、HTML、列表/表格、代码与图片排除、原位转换及数量限制；覆盖用户截图的两个链接和徽章，并验证原始文档不被修改。
- `GitHubCacheMigrationTest`：40→41 数据库升级保留已有文件夹，新增表可写可读；是 Android 用例，编译不等于在真机执行。
- 2026-09-10 对项目公开仓库发送一次无鉴权 GET，收到 HTTP 200、ETag 和额度响应头，服务端选用 API 版本 2026-03-10。没有发起仓库写入或消息发送。
