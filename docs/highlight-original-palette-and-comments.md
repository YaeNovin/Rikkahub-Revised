# 恢复 Highlight 原始配色与注释可读性

2026-09-28，工作区修复；不涉及渲染引擎、数学曲线或 HTML 执行策略。

## 问题与本次取舍

代码块一直使用项目的 Highlight 解析器，但此前又对全部语法角色进行通用对比度修正；无法覆盖混合背景时，还会重新计算色相／明度。这样会改变原来的 Atom One 配色，弱化角色之间的差异。

另一方面，原始调色板只按应用主题选择。透明代码块下方可能是与主题明暗相反的壁纸，因此浅色主题也可能需要深色版代码配色，反之亦然。

这次以用户要求的原始 Highlight 视觉风格为准：

- 保留原有 Atom One Dark / Light 调色板。关键字、字符串、数字、函数、类型、标点等角色的颜色不再逐项调色；不接受正文／背景取色模式将它们统一染色。
- 按代码块已合成的背景样本选择原始深／浅调色板。样本首先包含消息气泡和代码块自身的透明度，不能仅依据底下的壁纸；样本数相等时沿用应用主题。
- 仅修正 comment 槽位，行号沿用该槽位。单一确定底色上要求 4.5:1，对已可读的颜色不作额外修改。
- 不添加局部底色、不改变代码块背景或高级外观透明度设置。
- 保留整块解析、多行注释／字符串状态、语法作用域映射、源码预览 JSON 高亮和 32768 字符有界高亮；不回退此前的解析修复。

恢复原配色后，不再宣称每个彩色 token 在任意背景上都满足 4.5:1。跨越明暗极端的图片也不存在能保证每处可读的单一注释颜色，仍按现有策略尽力选择前景，不通过增加底色覆盖用户外观。

## 回归与设备样例

- `SyntaxContrastColorTest`：深色壁纸／浅色主题、浅色壁纸／深色主题、混合背景、缺失样本、覆盖壁纸的不透明表面；全部非注释色逐字段与原调色板比对；真实 Kotlin 高亮和多行注释保留。
- `TextContrastTest`：不同灰度／彩色底色与透明度下验证注释对比度，同时断言其他语法色不变及表面颜色不变。
