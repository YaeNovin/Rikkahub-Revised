# 最近记忆：仅记忆提取模型

## 使用与范围

入口：聊天页面 → 更多 → 最近记忆 → 本次对话记忆 → **仅记忆提取模型**。

- 使用后台记忆提取模型提取事实；情景记忆是否启用仍跟随助手设置。
- 当前对话不执行记忆 RAG 检索，不建立对话向量索引，提取出的新记忆也不调用向量模型建立索引。
- 已保存的有效记忆沿用基础记忆上下文提供给聊天模型，保留原有数量/长度预算和情景生命周期过滤。主模型不会因此挂载记忆创建工具。
- 只影响当前对话，不修改助手的共享设置，不影响知识库检索、其他对话或其他功能对向量模型的使用。
- 不删除旧记忆或旧索引。切回 RAG 后，现有索引可以继续使用；此前仅提取而无向量的记忆沿用现有文本检索回退。
- 新对话仍默认白板；分支继续继承创建时的记忆模式，不单独修改。
- 无可用提取聊天模型时，该新选项不可选并显示说明。已选该模式后若改为向量模型，不会偷偷恢复 RAG；界面提示需要更换提取模型。模型解析沿用现有规则：专用提取模型优先，其次旧配置的快速/聊天模型回退；面板显示实际解析的模型名称。

## 审查及修正

1. 原提取落库路径无条件建立向量索引，即使记忆 RAG 已关闭。本次将事实创建和情景替换的索引行为接入有效 RAG 设置。
2. 提取完成、持久化、情景状态更新和索引写入之前重新检查任务是否仍然有效，避免设置变化后的旧任务继续执行后续步骤。已发出的远程请求无法撤回；返回结果会重新校验。
3. 对话索引读取有效配置时改用最新助手设置，避免复用请求开始时的副本。取消/跳过的当前提取任务清理运行状态。
4. “最近记忆”按当前对话的实际配置显示状态、重试和索引片段，修复跟随助手/向量模式下的误报。RAG 关闭后收起索引展示，不删除数据库记录。
5. 模型能力诊断中，原来 `RAG_ONLY` 因 `enableMemory=false` 被误报为禁用；现在单独识别 RAG 是否启用。
6. 会话模式按名称存储，新增 `EXTRACTION_ONLY` 不改 Room 表结构；旧模式名称及默认值保持兼容。

## 验证

- 结果：44 项 JVM 测试通过，QA Kotlin 编译通过，3 项 Android 链路测试在 V2301A / Android 16 上通过。设备上整组运行出现等待，后两项改为独立运行并设置 30 秒超时后通过；不把被停止的整组运行计为通过。
- 44 项 JVM 回归：对话记忆策略、序列化与分支、提取节流、结果解析、对话片段索引和检索。
- QA Kotlin 编译和独立 debug 测试包编译。
- `MemoryExtractionOnlyTest` 使用临时内存 Room 和拦截的模拟 HTTP：验证仅提取模式保存记忆、基础上下文仍可用、没有向量请求；普通 RAG 仍建立向量；设置切换时丢弃迟到结果。
- 不调用真实模型，不读取用户的聊天数据库。完整界面选择体验另待用户测试。
- 本轮只更新独立 debug 回归包，常用 QA 包仍需后续重新构建、覆盖安装。
