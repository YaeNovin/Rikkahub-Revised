# 正文引号高亮修订与独立 Debug 验证

本次按用户提供的对话截图与背景图片验证用户、模型正文的双引号高亮。测试在独立包 `me.rerere.rikkahub.revised.quoteqa` 内运行，使用即时生成的随机对话，不发送真实模型请求，不读取原 QA 的会话或供应商配置。

## 原因与修订

模型的普通正文已有 Markdown → LinkText 高亮路径。参考场景中“不生效”的关键表现是颜色选择：复杂图片的极端亮暗样本会使旧算法选择过暗或过淡的颜色，部分气泡内还会与正文颜色趋同。解析有无命中与视觉是否形成强调需要分别验证。

此次修订保留文字取色的来源色相，提高 HCT 目标 chroma，并以实际 RGB 色域中的 chroma 评估鲜艳度。选择颜色时同时参考普通正文，减小正文与强调色趋同的问题；字重仍至少 SemiBold，不覆盖原有粗体或链接语义。

均匀背景优先保证普通文字的 4.5:1 对比度。复杂照片无法让一个鲜艳颜色对所有像素均满足该值，因此在鲜艳候选色内选择覆盖较好的颜色，并参考代表亮度；不承诺任意图片所有像素均达标，也不增加描边或额外文字底板。

HighlightCodeBlock 新增禁止正文装饰的作用域。Markdown、HTML 路径以及 LinkText 均尊重这个边界，避免代码内的嵌套显示重新启用引号/HEX 装饰；代码自身的字符串语法颜色仍由原高亮库决定。行内代码继续按 literal 注解排除。

## 验证范围

- JVM 回归：HEX 原文与复制偏移、双引号配对、单引号排除、代码/公式排除、HTML 局部背景、浅色/深色/AMOLED 对比度、复杂图片鲜艳度和紫色用户气泡的颜色区分。
- 真机：vivo V2301A、Android 16、USB ADB。以参考图片为真实绘制背景，调用项目的 Bitmap 采样和提色算法，再进入真实 MessagePartsBlock 渲染。
- 随机上下文：即时生成 8 条交替的用户/模型消息，包含普通正文、中文双引号、粗体、单引号、行内代码、HEX 和 Kotlin 围栏。
- 颜色模式：浅色自动清晰、浅色跟随应用背景、深色跟随应用背景、深色跟随手机壁纸；最后一项在测试夹具中使用从参考图提取的受控壁纸种子，不更改系统壁纸。
- 流式：未配对的双引号不高亮，补齐引号后对模型正文应用强调色。
- 开关：关闭后模型正文恢复普通颜色，代码 AnnotatedString 与语法样式保持相同。

测试夹具与构建 init script 位于 验证目录（本地证据，未公开）。独立包只保存夹具样本和截图，不向用户原会话写入内容。

测试基础设施曾因缺少 Toaster 的 CompositionLocal 中断代码围栏场景；该次属于夹具环境缺失，已独立保留输出。真机还发现深色图片会把强调色降低到约 16.53 chroma，此项用于继续修订候选色选择，不能用此前的纯色 JVM 结果替代真机验收。

## 最终结果

最终构建成功，29 项 JVM 测试全部通过；两组真机用例、14 条设备断言全部通过。

| 参考图场景（模型正文） | 普通正文 | 引号内部 | 实际 HCT chroma |
| --- | --- | --- | ---: |
| 浅色自动清晰 | #000000 | #6400F0 | 85.45 |
| 浅色跟随应用背景 | #390004 | #AD001E | 85.34 |
| 深色跟随应用背景 | #FFEFEE | #FF9F9A | 39.37 |
| 深色跟随壁纸种子 | #FFEFEE | #FF9F9A | 39.37 |

同一参考图的深色模型强调色从中间版本的 16.53 chroma 提升到 39.37，颜色与正文可区分。用户正文四种组合也全部通过；普通粗体保留，引号内字重至少为 600。均匀表面的最低对比度仍按 4.5:1 测试，复杂照片采用鲜艳度、对比度覆盖的折中，不宣称每个像素都满足该值。

代码围栏在高亮开关切换前后，包含 token 样式的 AnnotatedString 完全相同；行内代码保持原样。嵌套 Markdown 和 HTML 路径在禁止装饰的作用域内不能重新启用高亮。关闭开关后，模型普通正文中的引号恢复普通颜色。
