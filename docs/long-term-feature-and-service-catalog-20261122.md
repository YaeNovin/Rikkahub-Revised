# RikkaHub 长期功能与服务候选

这份清单回答用户以后可以在 RikkaHub 里做什么，以及哪些服务能支撑这些用途。候选分为**先做**、**第二阶段**和**探索**，表示建议顺序。依据是当前工作树和 Desktops、LingheChat、Yunzai 的本地实现及验证记录。上一轮的外部资料、KMP 迁移边界和工程路线见[长期演进审阅](long-term-evolution-review-20261122.md)。

## 建议先实现的组合

1. **收集到报告。** 分享一份 PDF 和一个网页到收集箱，加入项目，生成包含可点引用的短报告。验收报告能跳回 PDF 对应页或网页摘录，能够导出并在另一端重开。
2. **录音到笔记。** 导入一段音频，排队转写，校正字幕后输出带时间链接的 Markdown。验收暂停后仍可续办，导出字幕能回到正确时间。
3. **聊天到独立产物。** 保存一份谱面或图表，添加一次修订，切换分支并导出。验收旧消息版本仍可访问，源文件和 PDF/SVG 可独立使用。
4. **服务从可配到可用。** 统一显示模型、搜索和语音三个现有服务的连接状态，接入任务列表和实际用量。验收登录过期、地址不可用、取消和配额耗尽各有可理解的状态。

Android 可优先承担移动分享、录音和通知。Web 优先承担大屏阅读、研究和轻量工作台。Windows 的首批价值在本地文件、键盘和并排预览。KMP 首先共享消息/任务状态、引用锚点和产物交换规则，独立 WinUI 客户端可以先用同一组交换样例验证互通。

本轮是产品候选整理，核对了现有入口以及邻近项目资料。顺序由现有复用程度和可形成的用户闭环决定。实现、实际供应商账户能力、成本和设备表现留待对应候选验证。
