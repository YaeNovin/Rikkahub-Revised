# 世界书兼容性清单

本清单根据 SillyTavern [World Info 文档](https://docs.sillytavern.app/usage/core-concepts/worldinfo/) 和当前应用代码整理。保留来源字段不等于执行该字段；“已实现”仅表示本地评估器和界面有对应行为。

## 已实现

- 原生、独立 SillyTavern、Character Card V2/V3 世界书导入；V2/V3 角色卡内嵌世界书识别。
- 普通关键词、AND／OR／NOT 条件、正则关键词、大小写和完整词匹配。
- `scanDepth`／继承／当前输入／不扫描、扫描来源、常驻条目。
- 注入位置的本地映射、独立消息角色、插入深度、优先级、插入顺序。
- 单书和跨书 Token 预算、三种超限策略、导入报告、诊断和场景模拟。
- 概率、持续、冷却、延迟、生成触发类型、角色名称／标签过滤。
- 递归扫描基础、`preventRecursion`、`excludeRecursion`、`delayUntilRecursion`、递归级别。
- Outlet 名称与 `{{outlet::name}}` 拉取、组评分基础、版本历史、草稿、并发冲突保护。
- 条目分区编辑器：内容、触发、注入、高级、测试；世界书帮助与教程页。
- 全局、Persona、助手、Chat 显式绑定：新增来源管理页，可创建／编辑／切换 Persona，并为助手关闭继承。对话停用优先、同书去重，默认无全局／Persona 绑定。
- 插入策略：保留历史顺序、角色与全局按 Order 混排、角色在前、全局在前；新策略先排列 Chat、再 Persona。
- 导入条目扫描缓冲加入 `\x01` 消息分隔，名称前缀仍由 Include Names 控制；原生文本格式保持不变。
- 最少激活逐条扩大聊天窗口，在达到目标、预算／深度／安全上限时停止；延迟递归支持数字级别并逐级放行。单书预算跨扫描轮累计。
- NOT 条件命中不加组评分，Prioritize Inclusion 使用 Order；已采用的组跨扫描轮与世界书排他，避免多组交叉导致重复占组。
- 向量语义候选已接入真实生成链：默认关闭，需要选择向量模型并逐条启用 Vectorized。候选仍受绑定、角色、概率、分组、预算限制。
- 角色描述、性格、场景、角色备注、创作者备注、Persona 描述可作为额外匹配来源；新导入角色卡保留对应资料，来源页可编辑。
- V3 装饰器精确识别名称、验证参数并支持最多 8 层备用链；`activate_only_after/every` 按助手消息数计数，`scan_depth` 覆盖扫描深度；非正则模式支持 `additional_keys`／`exclude_keys`。

## 部分实现或有本地差异

- SillyTavern 数字位置 2/3（Author's Note）和 5/6（Example Messages）采用本地提示词位置映射，并非原始锚点。
- 跨书预算与复杂组竞争仍采用本地书级处理，而非完整复刻 SillyTavern 的全局候选池；单组／NOT 评分、跨轮预算和组排他已有回归测试，不代表所有竞争结果与上游完全相同。
- 为保护移动端，递归最多 32 轮，总扫描最多 1000 次；纯文本查询仍有本地计算预算。指定更大的上游数值不会无限执行。
- Persona 当前用于世界书绑定和额外匹配资料，不自动更改昵称、聊天模板或助手系统提示词。
- 向量查询最多取 8000 字符，每条索引取正文前 8000 字符；每次最多新建 32 个索引，20 秒后使用已完成结果与关键词。大世界书可能分多次补齐，不承诺首次请求索引齐全。
- 向量缓存与记忆索引隔离，按供应商／模型／参数／内容哈希失效，私有目录最多保留 1000 项。静态提示词预览、条目测试和场景模拟不调用向量 API。
- V3 `@@` 装饰器仅支持当前解析器列出的子集；未知装饰器保留但不会执行。
- Android Java Regex 与浏览器 JavaScript Regex 不完全等价；`g` 为无状态布尔匹配，`y/d/v` 和未知标志显示诊断。

## 建议验证顺序

1. 先在条目测试页验证单条关键词或表达式，再在场景模拟中逐轮验证深度、概率、持续和冷却。
2. 开启递归前先使用两个互相引用的短条目验证 `preventRecursion` 和 `excludeRecursion`，并设置 Token 预算。
3. 导入时保留源文件；新旧版本不要同时绑定，避免重复注入。
4. 用 `/\x01名字:[^\x01]*关键词/` 验证分隔符和名称前缀，注意 Include Names 和当前名称是否相符。
5. 向量功能会向所选供应商发送对话与条目文本，可能收费；先用少量条目验证，模型错误或未完成索引会在诊断中提示。Automation ID 仍不会执行脚本。

## 下一批需要独立设计的项目

1. 建立 Author's Note 和示例对话的原生结构后，再将 2/3/5/6 精确挂接，避免用新映射替换用户已编辑的位置。
2. 将候选收集与全局竞争选择分离，以实现跨书评分、预算、回溯和时间状态的完整差分测试。
3. STscript 需要独立解释器、权限白名单、逐次审批、执行上限及撤销策略。不能直接把导入文本传给 shell 或现有工具。
4. 导出前检测不能等价表达的原生设置，提供预览及明确的降级说明；不把字段复制当作无损互通。
