# 正式云母／亚克力外观与代码高亮修复

日期：2026-09-28。工作区实现，未发布正式版本。

## 正式外观

高级外观新增“云母与亚克力 → 应用云母 + 亚克力外观”：页面和侧栏设为云母，输入区和浮层设为亚克力。该操作只切换材质，保留背景文件、透明度、模糊半径及效果开关。各区域仍可单独选择，不强制覆盖为同一材质。

云母已接入真实页面、聊天底层、原有卡片配色，以及输入区／侧栏／浮层的材质分支。它不是透明玻璃：背景只用于取色，底层与卡片为低彩度、不透明的明暗层次；没有图片时使用主题色。染色强度保存为 `micaTintStrength`。旧小范围预览代码仍供固定样例验证使用，不再作为唯一入口。

## 模糊规则

| 材质 | 实际模糊 | 设置行为 |
| --- | --- | --- |
| 云母、实色 | 无 | 模糊与不适用的透明度置灰，原值保留 |
| 普通半透明 | 无 | 模糊置灰，透明度可调 |
| 磨砂、液态玻璃、亚克力 | 有条件启用 | 支持系统、效果已启用且来源可用时可调 |

亚克力属于玻璃类材质，继续使用上一阶段的输入区实时模糊与独立浮层快照模糊。

- 顶栏的通用实现和聊天专用实现都检查页面材质，云母／半透明不会因保留着旧“顶栏模糊”开关而继续模糊。
- 助手背景解析也遵守页面材质：非玻璃材质返回零模糊半径，但不删除助手原来保存的半径。助手设置中的相应滑块同步置灰。
- 浮层、侧栏与输入区保留未生效参数，切换回玻璃材质即可恢复。设备不支持、效果暂停或缺少采样源时仍沿用兼容回退。
- 背景开启和选图不自动改变页面材质。

## 代码高亮

后续调整见[恢复 Highlight 原始配色与注释可读性](highlight-original-palette-and-comments.md)：本节的整套语法色对比度／HCT 修正已由“原配色 + 注释单独修正”替代，多行解析及长代码修复保留。

排查确认了三个原因：

1. 复杂图片背景不存在覆盖所有明暗区域的单一文字色时，统一对比度算法回退到黑／白，导致多个语法角色合并成相同颜色。
2. 行号＋自动换行路径逐行解析代码，多行注释和多行字符串的语法状态丢失。
3. 普通代码超过 4096 字符后放弃高亮；部分细分语法作用域未映射到对应调色板槽位。

修改：

- 保留已可读的原色；无法全局满足对比度时，用既有 HCT 取色逻辑保留各语法角色的色相，避免整组语法色变成黑白。中性注释与标点仍为中性色。
- 整块代码只解析一次，再以 AnnotatedString 切分显示行，保留多行注释、字符串状态；CRLF 和末尾空行有单独回归。
- 类／类型、函数、布尔字面量使用相应调色板槽位，细分作用域继续向父作用域兼容回退。
- 聊天普通代码也显式启用最高 32768 字符的有界高亮；较长内容沿用后台解析和流式防抖。更大的内容仍原样展示，不截断源码，也不解除性能上限。
- 不添加正文或代码块补底，不改变高级外观中的代码表面透明度。不宣称任意透明图片背景上的每个像素都满足 WCAG 对比度。
