# 系统日志列表与详情展示

软件与系统日志现与请求日志采用相同的交互：点击列表条目打开详情面板，通过返回手势关闭。列表保持简短，长堆栈不再直接扩张整个列表。

## 显示内容

列表展示事件名称、时间、客户端版本与类型、错误类型、状态、来源及两行摘要。详情按字段分别显示：

- 时间、客户端、客户端标识、客户端类型、版本号。
- 错误类型、来源、状态、级别、摘要及可用的错误原因。
- 数据值：将 PSS/RSS、系统退出原因码、状态码、进程重要级别、渲染器、发生阶段、丢弃/持久化失败次数、追踪附件等拆为单独条目。PSS/RSS 明确为最后采样值并带 KB 单位。
- 记录 ID、采集会话 ID、请求 ID，以及已有的截断标记。
- 详细日志：复用请求日志正文组件，提供折叠预览、展开、收起、复制。长内容展开后使用固定高度的分块滚动视图，避免一次铺开整个堆栈。

请求日志的列表和预览布局保持原样；复用正文组件新增的折叠开关默认关闭，仅系统详情显式开启。导出和 AI 分析入口位于同一详情面板顶部。

## 客户端信息的真实性

新增可选的 `DiagnosticMetadata.client` 和 `errorType`，兼容已有 schemaVersion=3 记录。客户端保存名称、包名、版本名、版本号和构建类型；构建类型使用实际 `BuildConfig.BUILD_TYPE` 区分正式版、QA 测试版、Debug 测试版，不根据版本名字符串猜测。

普通事件随记录保存发生时的客户端信息；读取旧日志不补写当前版本。Java 崩溃首报同步保存当时的客户端信息，下次导入继续使用原信息；可选信息采集失败不会阻止最小首报保存。系统历史退出未提供当时版本时保持未知。旧记录缺少客户端或构建类型时显示“未记录”，不冒充当前安装版本。

异常入口保存明确的异常类型。旧堆栈在详情中可从异常链提取类型；系统退出、渲染、采集告警和普通事件按其已有来源分类。客户端和异常类型字段沿用统一脱敏及长度限制，也保留在摘要索引和导出中。
