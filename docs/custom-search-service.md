# 自定义搜索服务（JSON POST）

日期：2026-10-01。新增配置型搜索服务，保留所有原有服务及 Custom JS。

## 入口与配置

设置 → 搜索服务 → 右上角“+” → 自定义搜索服务。添加后进入配置页，可改名称并创建多个实例；聊天原有搜索服务选择入口会按同一列表显示。

| 配置 | 行为 |
| --- | --- |
| Base URL | 默认空，启用时必填；按 Base URL + 接口路径拼接，保留路径前缀 |
| 关闭 Base URL | 忽略已保存的 Base URL，接口地址必须填写完整 HTTP(S) URL；不隐式使用任何默认服务器 |
| API Key | 默认不勾选；勾选时必须填写，以 Authorization: Bearer 发送；关闭后不发送认证头但保留值 |
| 网页／X／其他 JSON POST | 默认网页路径 /v1/web_search，X 路径 /v1/x_search；仅切换已知默认相对路径，不覆盖手动完整 URL 或自定义路径 |
| model · 模型名称 | 选填，默认关闭且为空；仅勾选并填写非空模型名时发送 JSON 字符串，去除首尾空白。关闭保留值，留空/关闭均不发送；三个接口类型均可用 |
| max_results | 默认不勾选，编辑值默认 5；勾选后发送 1–20 的整数 |
| allowed_x_handles / excluded_x_handles | 仅在 X 类型下且勾选时发送字符串数组；逗号、空格、换行分隔，去掉开头 @ |
| from_date / to_date | 仅 X 类型且勾选时发送；严格日期校验，起始日期不能晚于结束日期 |
| 额外参数 | 每行独立勾选，支持文本、有限 JSON 数字、布尔、JSON 数组／对象／null；字段名不能重复或覆盖上面的保留字段 |
| 超时 | 本地网络策略，不放入 JSON；默认 60 秒，可设 10–180 秒 |
| 结果字段映射 | 本地解析策略，不放入 JSON；默认 results → url / title / snippet，支持 data.results 这样的点分对象路径 |

POST、Content-Type: application/json、Accept: application/json 和运行时 query 为固定项，界面显示但不可调整。所有可选请求字段只从手动配置生成，聊天模型仅提供 query，其他模型入参不透传。

未勾选 max_results 时不发送它，亦不以全局 SearchCommonOptions.resultSize 补入；服务端决定默认数量。本地仍限制最多接收 100 项，防止响应失控。勾选数量后按该数量保留返回结果。

取消勾选不会删除值，未勾选行的无效草稿也不会阻止请求。X 过滤在网页／其他模式下保留但不发送。名称、开关、草稿、参数类型和映射通过现有 Settings 序列化保存。

模型名由用户手动填写，不联动聊天模型选择，也不允许聊天工具调用参数覆盖。未发送 `model` 时由服务端决定默认模型，应用不会自动猜测默认值。模型名是否被接受取决于搜索服务自身的协议。

旧配置若有唯一一个文本类型的额外 `model` 参数，编辑器和请求构建会兼容迁移到专用模型项，保留启用状态和原值；编辑保存时写入新结构。重复或非文本的旧 `model` 行保留并提示冲突，避免静默丢失数据。新结构中额外参数不能覆盖专用 `model` 字段。

## 按用户提供截图配置

这是截图所述服务的配置示例，不是已验证的服务质量或官方承诺，也不会自动填入或请求该网站：

1. Base URL：`https://www.sui-xiang.net`（不要再附加 `/v1`，除非同步把接口路径改为 `/web_search`）。
2. 网页搜索路径 `/v1/web_search`；X 搜索改为 `/v1/x_search` 并选择 X 类型。
3. 按服务方要求勾选 API Key，填写其提供的密钥。
4. 按需勾选 max_results、X 账号／日期过滤；其余保持未勾选。
5. 默认结果映射适配 `{results:[{url,title,snippet}]}`。
6. 使用页面下方原有搜索测试按钮；这一步会真实联网，可能产生费用，需要用户主动执行。

关闭 Base URL 时，可直接填写完整的 `https://www.sui-xiang.net/v1/web_search`。完整 URL 不允许内嵌用户名、密码、查询参数或片段；请求参数统一由勾选项控制。HTTP 允许用于自建服务，但建议使用 HTTPS 保护搜索内容和密钥。

## 结果与边界

- 复用原有 SearchResult 和聊天搜索工具，因此引用编号、结果展示沿用既有流程。
- 缺少标题时使用占位标题，缺少摘要时为空；缺少结果数组／所有链接无效时明确报错，不误报“无结果”。只接收 HTTP(S) 结果链接，不执行服务端内容。
- 本接口不声明网页抓取能力，不假定提供者的对话接口支持内置 web_search/x_search。
- 不提供任意脚本、GET、表单、流式协议或任意认证头；本期适配同类 JSON POST 搜索服务。其他协议仍可使用原 Custom JS。
- 默认不跟随重定向，也不自动重试 POST，避免把密钥／搜索词转到其他目标或重复计费；需要填写最终接口地址。
- 响应限制 2 MiB，JSON 嵌套最多 32 层，额外参数最多 32 个，单值最多 8192 字符，请求最多 65536 字符。
- 错误不回显服务端响应正文或 API Key；HTTP 头日志对 Authorization 脱敏。取消搜索会取消底层 Call，并保留协程取消语义。
