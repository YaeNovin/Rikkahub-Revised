# 模型名称识别与深色文字配色修复

## 模型识别

模型能力、上下文默认值、参数适配和自动图标现在支持填写的模型名称。
名称可识别时优先使用名称；普通昵称无法识别时继续使用模型 ID。
例如 ID 为 `deployment-42`、名称为 `Google Gemini 4 Argon` 时，会匹配
Gemini 的能力及参数限制，请求中的模型仍是 `deployment-42`。

识别会处理大小写、空格、Unicode 连字符、常见厂商前缀和紧凑版本别名。
识别范围沿用项目已有模型注册表及参数族规则，不据此宣称未知模型支持新能力。

创建、改名和旧配置加载使用同一套识别逻辑。改名会更新原先的自动默认值；
与默认值不同的手动能力、模态及上下文限制会保留。旧配置只在加载时补齐，
保留原始模型 ID 和内部 UUID。

图标已用于模型列表、聊天头像、输入菜单、供应商模型设置和对话导出。
协议层的推理、采样、图像及视频特殊参数使用本地识别身份；
请求地址和请求体中的实际模型 ID 继续使用供应商配置。

## 深色模式文字

亮壁纸上的页面文字可能需要深色，但叠在页面上的深色卡片需要浅色文字。
原先全局可读性主题修改 `onSurface` 后，卡片中显式读取这一角色的文字
会继承页面的黑色，绕过卡片自己的前景颜色。此问题也影响设置项。

`AppearanceCard` 和 `CardGroup` 现在按各自表面的实际前景颜色设置局部文字
角色，使显式主题色和继承文字色一致。高级外观页的说明卡片也使用这一规则。
公共返回按钮同时设置表面的前景色，避免只替换背景后仍使用黑色默认图标。
浅色但有彩度的背景也可继续提取色调，
避免不必要地退化为纯黑。文字最终仍需通过实际背景的对比度判断。

保留了亮背景上必要的深色文字；没有将所有页面强制改为白字。

## 验证入口

- JVM：`ModelNameMatchingTest`、`ModelParameterFamilyTest`、
  `ModelIconMatchingTest`、`ProductionDarkPaletteTest`，以及现有 AI/应用测试。
- 图像请求回归检查名称匹配后的参数限制与原始请求 ID。
- 真机：`AppearanceModeRegressionActivity` 使用生产主题和材质组件，
  配合 `scripts/verify_appearance_modes.py` 检查五种正文区域的实际截图像素。
  覆盖液态玻璃、云母，深色/无图/亮色背景，四种文字模式及重复切换，
  可通过 `--amoled` 使用纯黑表面。

此轮验证不调用付费在线模型。QA 使用覆盖安装，保留用户数据及首次安装时间。
